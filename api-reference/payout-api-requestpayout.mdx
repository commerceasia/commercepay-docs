Used to request a payout and transfer funds to the specified recipients through a bank account or DuitNow Proxy.

<Note>
A successful response means the payout request was accepted and queued, not that the funds have been transferred. To get the final payout status, use the `callbackUrl` ([Callback Notifications](/callback-notifications)) or call <Badge color="blue">API</Badge> [Query Payment](/api-reference/query-payment).
</Note>

## Before you begin

The request is rejected if any of the following is not met:

- Your [wallet](/payout-integration#wallet) for the payout currency is active and has sufficient balance.
- The payout channel is enabled for your merchant account.
- The IP address of the server calling this API is whitelisted, if IP whitelisting is configured for your account.

## Request

### Headers

<CommonHeaders />

### Body

<ParamField body="channelId" type="integer" required>
  An identifier that represents a CommercePay payments channel.

  | Environment | Payout channelId |
  | ----------- | ----------------- |
  | Staging | `15` |
  | Production | `9` |

  See the [Channel List](/channel-list) for other channel values.
</ParamField>

<ParamField body="providerChannelId" type="string" required>
  An identifier that represents the payment method (Bank or DuitNow Proxy). You can obtain the providerChannelId via the <Badge color="blue">API</Badge> [Get Provider Channels](/api-reference/get-provider-channels) or refer to it [here](/payout-provider-channel).
</ParamField>

<ParamField body="currencyCode" type="string" required>
  Currency code with a 3-letter ISO 4217 standard code (e.g., `MYR`).

  Maximum string length: `3`
</ParamField>

<ParamField body="amount" type="int64" required>
  The transaction payment value. This field exclusively accepts integer units where the final decimals are represented as whole values (e.g., an amount value of `1050` translates to `10.50` in the system backend).
</ParamField>

<ParamField body="referenceCode" type="string" required>
  The merchant-side unique order reference or invoice tracking sequence code.

  Maximum string length: `50`
</ParamField>

<ParamField body="description" type="string" required>
  Short free-text summary of the transaction.

  Use English letters, numbers, spaces and basic punctuation (`. , - _ ( ) @ /`). Avoid emojis and non-English characters: some payment providers remove unsupported characters or shorten the text before using it, so the description shown by the provider may differ from what you sent. The payment is not rejected when characters are removed.

  Maximum string length: `100`
</ParamField>

<ParamField body="ipAddress" type="string" required>
  The customer's IP address captured by the merchant server.

  Maximum string length: `50`
</ParamField>

<ParamField body="userAgent" type="string">
  **[Conditional]** Customer's user agent. It is recommended to input for a better user experience for specific channels due to different platforms such as desktop, mobile, or app view. Example channels impact: ShopeePay.

  Maximum string length: `200`
</ParamField>

<ParamField body="returnUrl" type="string" required>
  The synchronous return URL where the customer's browser is automatically redirected after the transaction is completed.

  Maximum string length: `500`
</ParamField>

<ParamField body="callbackUrl" type="string">
  A URL provided by the merchant to receive server-to-server notifications from the system regarding transaction status updates. This URL is called automatically once the payment process is completed or when the transaction status changes. See [Callback Notifications](/callback-notifications) for the payload and signature verification steps.

  Maximum string length: `500`
</ParamField>

<ParamField body="customer" type="object" required>
  <Expandable title="properties">
    <ParamField body="customer.email" type="string">
      Customer's email address.

      Maximum string length: `150`
    </ParamField>
    <ParamField body="customer.mobileNo" type="string">
      **[Conditional]** Customer's mobile number. Required when `providerChannelId` is `MBNO` (DuitNow Proxy using a mobile number).

      Maximum string length: `16`
    </ParamField>
    <ParamField body="customer.name" type="string">
      **[Conditional]** Customer's name. For a bank payout, this is the beneficiary's account holder name. Required when `providerChannelId` is a bank code (payout via bank account).

      Maximum string length: `36`
    </ParamField>
    <ParamField body="customer.username" type="string">
      **[Conditional]** The beneficiary's bank account number, national ID (NRIC) or Business Registration Number. Required for a bank payout, and for DuitNow Proxy payouts where `providerChannelId` is `NRIC` or `BREG`. Not required when `providerChannelId` is `MBNO`; use `customer.mobileNo` instead.

      Maximum string length: `36`
    </ParamField>
  </Expandable>
</ParamField>

<ParamField body="localCitizen" type="boolean" required>
  If the customer is Malaysian, set this to true; otherwise, set it to false.
</ParamField>

<ParamField body="timestamp" type="int64" required>
  Numeric timestamp in milliseconds representing request validation freshness, generated via `new Date().getTime()`. Example: `1621851652617`.
</ParamField>

## Response

### Body

<ResponseField name="currencyCode" type="string">
  Payout currency.

  Maximum string length: `3`
</ResponseField>

<ResponseField name="amount" type="integer">
  Payout amount. For example, 1050 represents 10.50.
</ResponseField>

<ResponseField name="transactionNumber" type="string">
  Unique CommercePay Transaction Number.

  Maximum string length: `24`
</ResponseField>

<ResponseField name="channelId" type="integer">
  An identifier that represents a CommercePay payments channel.
</ResponseField>

<ResponseField name="redirectionType" type="integer">
  Represents the **redirectUrl** type. This field returns 1 (URL redirection).
</ResponseField>

<ResponseField name="redirectUrl" type="string">
  URL used for the customer to redirect to the payment page.
</ResponseField>

## Error Responses

| Code | Description |
| ---- | ----------- |
| 1 | `Invalid Signature.` |
| 2002 | Invalid payment amount. |
| 2004 | The currency is not supported by the payout channel. |
| 2005 | The amount is below the minimum allowed for the channel. |
| 2006 | The amount exceeds the maximum allowed for the channel. |
| 2008 | `Failed Payment Request`. The request failed without a provider message. |
| 2009 | Duplicate transaction. |
| 2016 | The channel is not enabled for your merchant account. |
| 2019 | `providerChannelId` is required. |
| 2056 | The request was rejected by the payout provider. The `message` states the reason, for example `Failed Payment Request (Description: Missing CustomerUsername or CustomerName)`, `Failed Request (Description: Tenant wallet insufficient fund)`, `Failed request due to Wallet Inactive` or `Failed Request (Description: IP Address not in whitelist)`. |
| 2196 | The channel has been switched off by the merchant. |

```json Response_400
    "message": "Failed Payment Request"
  }
}
```
